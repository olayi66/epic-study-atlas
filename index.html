How Epic fits together

Epic is one database with many applications on top. Each application is owned by a different team (access, clinical, ancillary, revenue), but they all read and write the same patient record. Learn the patient's path first, then the data layers.

Vocabulary

Chronicles building blocks

  • Master file (INI): a "drawer" holding one type of thing, such as EPT for patients.
  • Record: one entry, such as one patient.
  • Item: one field on the record, written like EPT 88402.
  • Contact: a dated slice of a record. Encounters are contacts on the patient, identified by the CSN.
  • Static vs dynamic: static files hold build (EAP procedures, ERX meds); dynamic files grow with care (EPT, ORD).
Keys to memorize

IDs you will see everywhere

  • PAT_ID: the patient record. Joins nearly every clinical table to PATIENT.
  • PAT_ENC_CSN_ID: contact serial number, unique for every encounter across all patients.
  • PAT_ENC_DATE_REAL: encounter date as a decimal; .00 is the first contact that day, .01 the second.
  • HSP_ACCOUNT_ID: the hospital account (HAR) that billing hangs off.
  • ORDER_PROC_ID / ORDER_MED_ID: procedure and medication orders.
